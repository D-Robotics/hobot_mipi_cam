## 1. 范围与总分结构

评测分 **5 个计分模块**，资源与短稳为**门槛项**（不计分，不达标一票否决）：

| 模块 | 权重 | 子包（分析/报告单元） |
|---|---|---|
| 图像采集性能 | 22 | `eval/analysis/acquisition` |
| 时间戳与多流同步 | 28 | `eval/analysis/sync` |
| IMU 单体 | 11 | `eval/analysis/imu` |
| Camera-IMU 关联 | 17 | `eval/analysis/cam_imu` |
| 接收链路 | 22 | `eval/analysis/receiver` |
| **合计** | **100** | |

> 「5 个子包」是**分析与判定单元**，不是运行单元。实际开发按**指标级分支**推进（见第 7 章），每个分支只加该指标的直接证据；同一子包内多个分支的结论合并成该模块报告。

### 1.1 本期做什么

- 设备侧：帧率、丢帧、启动、间隔稳定性、分辨率、时间戳/同步、曝光与延迟、IMU、Camera-IMU。
- 接收侧：接收丢帧、单调性、延迟、带宽、多订阅者、负载影响、多流同步。
- 资源与短稳：CPU、RSS、fd、温度、30min 短稳、5–10 次启停。

### 1.2 本期明确不做

| 项 | 原因 | 报告处理 |
|---|---|---|
| 24h/8h/2h 长稳 | 时间预算不足 | 30min 短稳替代，标注「长稳未测」 |
| 50 次启停 | 时间预算不足 | 5–10 次替代 |
| 图像质量（清晰度/噪声/色彩/白平衡） | 主观项，定稿已移出计分 | 人工抽检记录，不计分 |
| 1920x1080 / 960x540 sensor 模式 | 仅有 sc132gs | 仅测 VSE 输出尺寸，标注「非 sensor 原生模式」 |
| LED/敲击/棋盘格/六面翻转 | 纯软件测试约束 | 标注「未测，条件不具备」 |
| VIMS / grab failed | 独立工作，已解决 | 不纳入 |

## 2. 设计原则（本方案的硬约束）

### 2.1 直接证据优先

**只记录事件发生点的原始量，不靠旁证反推。**

| 类别 | 允许 | 禁止 |
|---|---|---|
| 丢帧 | 在真实丢弃点计数：`get_empty_buff` 回收、`FrameQueue` 满丢/`popUntil`、`getframe` 失败、`empty_null`、`select` 超时 | 用间隔抖动、CPU 占用、fps 偏低「猜」丢帧 |
| 延迟 | `frame_in` / `pub_out` / 配对点的单调时钟时间戳 + 曝光中点 | 用订阅间隔近似发布延迟 |
| 左右目同步 | `sync_task` 配对处的 `ts_diff` | 事后按最近邻「凑」配对 |
| 接收丢帧 | 发布端 `pub_out` 计数 vs 接收端 recorder 计数，两端对账 | 只看接收端频率推断丢帧 |
| 帧率/抖动 | 原始帧时间戳序列的计数与差值 | 用 CPU 负载解释帧率 |

两类特殊说明：

- **硬件序号缺口**（`frame_id`）作为 VIN 侧丢帧的**直接计数器轨迹**，不是猜测；但只用于归因，不作为丢帧率主口径。
- **IMU 丢样**若无硬件样本计数器，只能由硬件采样时间戳缺口直接算出缺失样本数；报告需注明口径。

### 2.2 零侵入

- 默认 `eval_log_enable=false`，关闭时不产生任何输出、不改变数据通路与产品日志。
- 开启时只做旁路打点；不在热路径加锁、不改变队列/发布/线程行为。
- 产品 launch 文件不改；评测 launch 放 `eval/launch/`。

### 2.3 分支隔离 + 参数控制（混合）

- **代码怎么进仓库**：按指标分支，一个分支只包含该指标的直接证据与解析，diff 干净可回滚。
- **一次运行开哪些日志**：只用一个参数 `eval_log_events`（事件类别逗号分隔），默认全关。
- 不采用「每指标一个 bool 参数」：参数爆炸、易漏关、与现有契约冲突。
- 关键拆分：`frame_in`（时序/序号）与 `exposure`（触发/曝光）是**两个独立事件**，各自分支独立引入，运行时也可单独开。

### 2.4 基线定标

- 先跑 3 个基线用例：单目 30fps、双目全配、7/8 非整数帧率。
- 基线阶段只统计、不判定；分析工具给出建议阈值（延迟/抖动类取 p95×1.2，硬性项参考需求文档），人工评审后写回 YAML。
- 未定标指标报告显示「基线模式：仅统计」。

## 3. 被测数据通路与可观测点

```
sensor ─> VIN ─> ISP/VSE/GDC ─> hbn_vnode_getframe ─> memcpy 入 VideoBuffer
                                      │
                                      ├─ v_buff_que_manger_[i]（主码流，深度≈3，满 3 回收最旧）
                                      ├─ v_sub_buff_que_manger_[i]（辅码流）
                                      └─ v_frame_que_[i] ─> sync_task ─> combine_buff_que
发布线程（每 topic 一个）：getFrame(队列取帧) ─> [bgr8 NEON 转换] ─> publish ─> DDS/hbmem ─> 订阅端
IMU：IIO/event ─> read_imu_data 线程 ─> /imu_data + /imu_extrinsic + static TF
```

### 3.1 可观测点清单

| 观测点 | 位置 | 可得到的直接量 | 用于指标 |
|---|---|---|---|
| 启动阶段 | `HobotMipiCapIml::init/start`、node 构造、首帧/首次发布 | 各阶段单调时刻 | 首帧启动时间 |
| 取帧 | `multiFrameTask` / `subMultiFrameTask` 的 `getVnodeFrame` 成功后 | `frame_id`、`ts_frame`、宽高、pipe/stream | 帧率、间隔、单调、重复、分辨率 |
| 取帧失败 | `getVnodeFrame` 返回非 0 | ret、pipe/stream | 丢帧（直接） |
| 缓冲区 | `BuffQueueManage::get_empty_buff` | 回收最旧帧次数、返回空次数 | 丢帧（直接） |
| 拼接队列 | `FrameQueue::push` / `popUntil` | 满丢/过期丢累计数 | 丢帧（直接） |
| 曝光 | `getVnodeFrame` 内 `tv/trig_tv` | `ts_trig`、`ts_hw`、`exp_us` | 曝光中点、延迟 |
| 同步配对 | `sync_task` / `sub_sync_task` | 两侧 `frame_id`、`ts`、配对差 | 左右目同步、配对率 |
| 拼接产出 | combine 帧生成处 | `ts_combine`、`ts_left`、`ts_right` | 拼接 ts 一致、额外延迟 |
| 发布 | node `imageUpdate` / `hbmemUpdate` | 发布时刻、topic、seq | 发布延迟、接收对账 |
| 订阅 | C++ recorder | 接收时刻、header stamp、序号、宽高 | 接收延迟、丢帧、单调性 |
| IMU | `/imu_data` + `imu_probe` | header stamp、ax/ay/az/gx/gy/gz | 频率、抖动、丢样、有效性、Camera-IMU |
| 资源 | `/proc/<pid>`、pidstat、thermal | CPU/RSS/fd/温度 | 门槛项 |

### 3.2 可复用的既有诊断资产

来源分支：`feature/x5-capture-diag-log-v2`。**只复用逻辑/结构，不整体 merge**。

| 可复用 | 用途 |
|---|---|
| `FrameQueue::dropped_total()` / `size()` / `dump_ts()` | 队列丢帧直接计数 |
| `BuffQueueManage::size_data()/size_empty()` | 队列水位 |
| `PipeDiag`（heartbeat/select_wake/select_error/select_timeout/getframe ok,fail/empty_null/fid_advanced） | 采集链路逐环节直接计数 |
| `SyncDiagStats`（ts_diff/fid_diff 直方图、side stall、sync_ok/fail、drop） | 左右目配对直接差值 |
| `PubDiag`（pub/cons ok,fail、subscribers） | 发布端/订阅端对账 |
| `VideoBuffer::sys_timestamps` | realtime 口径 |
| `apply_diag_log_level()` | 防止全局 `warn` 静音评测日志 |

| 必须改造 | 原因 | eval 做法 |
|---|---|---|
| `diag_enable_` 默认 true | 违反零侵入 | 默认 false，只认 `eval_log_enable/events` |
| `RCLCPP_INFO("diag ...")` | 非契约格式 | 改 `[EVAL] key=value` |
| `pair queue ... (push)` 每帧 dump | 日志洪水 | 删除，改 `queue_stat` 周期计数 |
| 10s 周期 | 粒度粗 | 1s 周期或按事件直出 |
| `fid_missing = delta − ceil(sensor_fps/app_fps)` | **推算**，辅流/非整数帧率/回绕会失真 | 丢帧主证据改真实丢弃点计数；`fid_missing` 仅作交叉验证并标注 |
| `combine_pair_log_enable_` 默认 true | 违反零侵入 | 默认 false，归入 `sync_pair` |

## 5. 事件契约

### 5.1 行格式（不变）

```
[EVAL] ts_mono=<int64 ns> event=<name> <key=value ...>
```

- `ts_mono` 由 `EvalLog::emit` 自动写入，CLOCK_MONOTONIC 纳秒。
- 所有时间字段一律 int64 纳秒；禁止 µs/ms 混入。
- 输出到 stdout，行缓冲；运行统一 `--ros-args --log-level warn` 压掉产品日志。

### 5.2 事件与字段

| 事件 | 关键字段 | 引入分支 |
|---|---|---|
| `startup` | `stage=node_init/vflow_start/first_frame/first_pub`、`dur_ms`、`pipe` | B01 |
| `frame_in` | `pipe`、`stream=main/sub`、`frame_id`、`ts_frame`、`width`、`height` | B02/B04 |
| `exposure` | `pipe`、`stream`、`frame_id`、`ts_trig`、`ts_hw`、`exp_us`、`exp_valid`、`stamp_src=sensor/realtime/trig` | B05 |
| `frame_drop` | `pipe`、`stream`、`reason`、`frame_id`、`ts_frame` | B03 |
| `sync_pair` | `tag=main/sub`、`pipe_a`、`pipe_b`、`frame_id_a`、`frame_id_b`、`ts_a`、`ts_b`、`diff_ns`、`ok` | B06 |
| `combine_out` | `tag=main/sub`、`ts_combine`、`ts_left`、`ts_right`、`width`、`height` | B07 |
| `queue_stat` | `pipe`、`main_depth`、`sub_depth`、`combine_depth`、`recycled`、`fq_drop`、`empty_null` | B03 |
| `error` | `err`、`pipe`、`ret` | 既有 |
| `imu_error` | `err`、`detail` | 既有 |
| `imu_sample`（可选） | `ts`、`seq` | B12（仅短测） |

### 5.3 开关与过滤

- `eval_log_enable`（bool，默认 false）
- `eval_log_events`（string，默认 `all`）：逗号分隔事件名，如 `frame_in,exposure,pub_out`。
- 未知事件名告警并回退 `all`（既有行为），避免静默零输出。
- `frame_drop` 限流：`getframe_fail`/`select_timeout` 逐次输出；`queue_recycle`/`fq_full`/`fq_expired` 只进 `queue_stat` 周期计数，避免严重丢帧时日志自身成为负载。

### 5.4 跨平台兼容

- S100 现有 `frame_in` 同时带 `exp_us/exp_valid`；X5 把曝光拆到 `exposure` 事件。
- 分析链优先读 `exposure`，缺失时回退 `frame_in` 的同名字段；S100 产物无需改动即可继续分析。

## 6. t0、时钟域与延迟口径

### 6.1 曝光中点 t0

| 场景 | t0 计算 | 域 |
|---|---|---|
| lpwm / `trig_valid=1` | `t0 = ts_trig + exp/2` | 硬件域（通常 realtime），用 clock sidecar 归一到 monotonic |
| `frame_ts_type=sensor` | `t0 = ts_frame − exp/2` | monotonic |
| `frame_ts_type=realtime` | `t0 = header_stamp + exp/2`（X5 的 realtime stamp = `sys_timestamps − exposure`，即曝光开始） | realtime，归一到 monotonic |

> 现有分析链一律按 `stamp − exp/2`，在 realtime 模式会差一个曝光时长；本方案按上表修正。

### 6.2 域归一

- recorder 启动时背靠背采样 `realtime` 与 `monotonic`，写 `<csv>.clock`（偏移 ns）。
- 分析时把 IMU（REALTIME）与 realtime 口径的相机 stamp 统一减偏移到 monotonic 轴。
- 运行期间若发生时钟跳变（NTP/手动改时），偏移失效；报告需标注并剔除跳变窗口。

### 6.3 延迟定义

- 设备侧获取延迟：`frame_in.ts_mono − t0`（`ts_mono` 在 `memcpy` 完成后打点）。
- 设备侧发布延迟：`pub_out.ts_mono − t0`（`ts_mono` 在 `publish()` 返回后打点；**不含 DDS 实际传输**）。
- 接收延迟：`recorder.recv_mono − t0`（同机同钟域）。
- 拼接额外延迟：combine `pub_out.ts_mono − 同帧 left pub_out.ts_mono`。

## 7. 分支施工序列

### 7.1 分支工作流（每个指标一个循环）

1. **开工前先汇报**：本轮测什么指标、用哪个用例/配置、准备加哪些 log/事件、预期产出、预计时长；**得到用户同意后再动手**。

3. 只实现该指标的直接证据事件 + 分析 + 用例 + 单测；不夹带其他指标字段。
4. 交叉编译 X5（docker humble 套件，`PLATFORM_X5=ON`），板端跑对应 case。
5. 分析链产出该指标 JSON/Markdown 片段；先看 `result.txt`、节点/recorder 日志和分析结果：

7. 分支合回 `feature-eval`；下一分支从更新后的基线开出。

> 基线累积后，分支 N 的 diff 仍只含指标 N；此前分支的日志代码已合入但**默认全关**，运行时用 `eval_log_events` 只开当前指标。

### 7.3 Review 子代理协议

**触发条件**：只在 `result.txt`/节点日志/recorder 日志/分析结果出现异常，或新日志语义不确定时启动；
日志干净时不跑评审，避免为“正常”付额外成本。

- 类型：`general-purpose`，**只读**，不继承主对话结论；prompt 只给分支 diff + 指标定义 + 事件契约。
- 必查项：
  1. 打点位置是否在事件真实发生点（拷贝前/后、丢弃前/后是否搞反）；
  2. 单位/位宽/溢出（int64 ns、µs、有符号、timespec 换算）；
  3. 时钟域（mono/realtime/trig）与换算；
  4. **是否直接反映指标**，有没有需要反推的字段；
  5. 分支覆盖（单目/双目/辅流/拼接关闭时是否漏打）；
  6. 零侵入（关闭时零输出、热路径无锁/无格式化开销）；
  7. 与解析器/分析公式是否一致；
  8. 用合成数据手算数值自洽性；
  9. 边界/反例：给出至少一个会暴露盲区的用例（如 frame_id 回绕、辅流 fps≠主频、trig 为零、单侧停摆）。
- 输出：`{严重级别, file:line, 问题, 证据, 建议}`；无问题写 PASS；**不得修改文件**。

## 9. 评分与门槛

### 9.1 两阶段

1. **基线阶段**：C01/C06/C09 各跑一次，输出统计 + 建议阈值；报告标注「基线模式，不判定」。
2. **正式阶段**：人工确认阈值写回 YAML，跑核心矩阵，三态评分 + 门槛判定。

### 9.2 三态评分

- 满分：达标；
- 线性扣分：介于合格线与 0 分线之间，按比例；
- 0 分：低于 0 分线。
- 模块分 = 指标均值；总分 = Σ 模块分 × 权重。
- 门槛任一项 FAIL → `GATE-FAIL`，总分记 0。
- 与基线 Δ%：±20% 标黄提示，不直接判 FAIL。

### 9.3 未测项处理

- 未测指标不参与模块均值，报告单列「未测」并在总分旁标注覆盖率；不静默按 0 分。
