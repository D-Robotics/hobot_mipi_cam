## 一、已定决策（18 项）

### 总体约束

1. **目录**：评测代码与输出全部收在 `hobot_mipi_cam/` 包目录内，不建顶层独立包。
2. **跨平台**：评测方案适配所有平台，编译时才针对平台分化；埋点预埋只做 **X5/S100/S600** 三平台后端（x3/rdkultra 暂不处理，接收端指标仍可跑，设备侧指标标"平台未埋点"）。
3. **零侵入**：埋点不修改产品逻辑与输出——默认关闭时驱动行为与现有产物完全一致；开启时只加旁路观测输出，不动数据通路控制流（ADR-0001 同源原则）。
4. **阈值不定死**：先开发评测程序跑基线统计实际指标分布，再定各指标判断阈值（基线定标模式）；原方案表中的量化标准降级为"初始期望值"注释，不作判定依据。

### 技术裁决

| # | 决策点 | 结论 |
|---|---|---|
| 5 | 设备侧指标获取 | 驱动内 log 埋点（平台后端预埋，统一接口统一格式） |
| 6 | 接收端 recorder | **C++**（rclpy 方案否决——全配带宽下 Python 会自身丢帧污染数据） |
| 7 | 埋点事件集 | 6 类：startup / frame_in / pub_out / queue_stat(1s周期) / error / imu_error；IMU 不逐条埋（200Hz×8h 日志本身成负载）；ISP/GDC 不单独埋 |

| 9 | 埋点开关 | 运行时参数 `eval_log_enable`（默认关）+ `eval_log_events` 类别过滤；`[EVAL]` 前缀单行 key=value 走 stdout，不写独立文件 |

| 14 | 负载制造 | stress-ng 按核折算 30/50/80%（无则 yes 进程替代，报实测值）；被测+recorder 用 taskset 固定保留核；烤机只跑双目全配 0.5/1/2/8h |
| 15 | 构建形态 | `eval/` 为嵌套独立 ament 包 `mipi_cam_eval`（C++ recorder + Python 分析 + launch + cases），不依赖 PLATFORM 宏，三平台同产物；主包 CMakeLists 零改动 |

### 评分与流程

16. **评分**：每指标三态（满分/线性扣/0），模块分=指标均值；**权重定稿**（图像质量移出后按比例摊派，合计 100）：

| 模块 | 权重 |
|---|---|
| 图像采集性能 | 22 |
| 时间戳与多流同步 | 28 |
| IMU 单体 | 11 |
| Camera-IMU 关联 | 17 |
| 接收链路 | 22 |

同步类合计 45。资源消耗与 24h 长稳为**门槛项**：不计分、不达标一票否决（GATE-FAIL 总分记 0）。图像质量属人为任务，本期不评不处理（后续引入需重新分配权重）。

17. **基线定标**：基线用例每平台 3 个（单目标称 / 双目全配 / 非整数帧率 7-8），YAML 标 `baseline: true`；分析工具按分布自动建议阈值（p95×1.2），**人工评审后**写回 YAML；未定标指标报告显示"基线模式：仅统计"；基线数据入库 `eval/reports/baselines/`。
18. **回归呈现**：正式报告附与基线的 Δ% 偏移表，±20% 标黄仅提示不判 FAIL。

## 二、目录与数据流

```
hobot_mipi_cam/
├── include/hobot_mipi_eval_log.hpp   # 统一埋点接口
├── src/{s100,x5,s600}/…              # 三平台后端预埋 [EVAL]
└── eval/                             # ament 包 mipi_cam_eval
    ├── src/recorder.cpp              # C++ 多topic订阅 + 双钟偏移采样 + CSV
    ├── launch/  cases/               # 用例与平台覆盖层
    ├── tools/analyze/                # 域归一/统计/评分/定标建议
    ├── logs/（gitignore）  reports/（含 baselines/）
```

数据流：埋点 `[EVAL]` 行 + recorder CSV → 分析（域归一 → 指标统计 → 三态评分 + delta 表）→ skill 编排全流程 → 报告。

## 三、关键代码事实（定稿依据）

1. **时间戳跨域**：图像 `frame_ts_type=sensor` → `info.timestamps`（monotonic 域）；IMU 三路径（evdev 默认优先/IIO/sysfs）均为 CLOCK_REALTIME 域——未归一直接计算 Camera-IMU 同步会差"开机 epoch 偏移"。
2. **曝光时长**：`tv−trig_tv` 三平台 `getVnodeFrame` 均已在算（X5 有 trig_tv 零值守卫=存在无效场景；S100/S600 PYM group 路径未算需补）；现有变量 int32_t ns，埋点须 int64。
3. **平台语义差异**：X5 `realtime` = `info.sys_timestamps`（已减曝光），S100/S600 = 本地读时刻或偏移换算——同参数跨平台不可直接对比，cases 平台覆盖层标注。
