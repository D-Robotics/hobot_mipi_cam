## 1. 结论速览

| 用例 | 各 pipe 帧数 | 配对数 | 配对率 | 差 p50(ms) | p99(ms) | max(ms) | frame_id 错配 | 失败事件 | 配对停顿 |
|---|---|---|---|---|---|---|---|---|---|
| C04 | 5175 / 5175 | 5174 | 99.98% | **2.96** | 2.99 | 3.07 | 0 | 0 | 无 >50ms |
| C07 | 5189 / 5188 | 5188 | 100% | **1.28** | 1.30 | 9.80 | 0 | 0 | 无 >50ms |
| C04S | 5014 / 4950 | 4937 | 99.74% | **2.97** | 2.99 | 3.01 | 0 | 3 | 负载期 287 次 >50ms；全程 max 150ms |

- **配对算法本身正确**：三例 `frame_id_a != frame_id_b` 均为 0，没有出现“时间戳接近但配错帧”。
- **LPWM 把左右 stamp 差从 2.96 ms 降到 1.28 ms**；C07 的剩余 1.28 ms 与左右**曝光时长差**（5991−4705 = 1286 µs）几乎相等，来自两目 AE 未同步。两者都超过飞书 1 ms 口径（口径问题见 §5）。

## 2. 配对时间差（B-02）

- 分布高度集中，不是随机抖动：
  - C04：p50 2.96 ms、p99 2.99 ms（p99−p50 仅 0.03 ms）；
  - C07：p50 1.28 ms、p99 1.30 ms，首帧一个 9.80 ms 离群点，之后稳定；
  - C04S：p50 2.97 ms，与 C04 相同。
- **与曝光数据的同 run 交叉验证**：C07 的 `exp_us` 左右为 4705 / 5991 µs，差 **1286 µs**；配对差 p50 = **1283.5 µs**，两者只差 2.5 µs。两 pipe 共享同一 `ts_trig`，`tv = trig + exp`，所以**帧就绪时刻的差 = 曝光时长差**；配对 stamp 差正是这 1.28 ms。
- 结论：C07 剩余的 1.28 ms **不是取帧路径差，而是左右 AE 曝光时长不同**（`sync_ae` 默认 false）。
- C04 的 2.96 ms 含“曝光起点相位差 + 曝光时长差”。用 C07 标定的时长差 1.28 ms 扣减，**曝光起点相位差 ≈ 1.68 ms**（估算，非直接测量）。
- 跨轮复核：上一轮 C04/C07 为 3.16/1.30 ms，本轮为 2.96/1.28 ms；**run 内极稳、run 间有 ~0.2 ms 波动**，与每轮 AE 状态有关，不能当绝对常量。

## 3. 配对率（B-03）与吞吐

- C04：5174/5175 = 99.98%（1 帧未配上）。
- C07：5188/5188 = 100%。
- C04S：4937/4950 = 99.74%（低于 99.9% 基线）。
  - pipe0 5014 帧、pipe1 4950 帧，**单侧少 64 帧**；
  - 按 fps 归一化：pipe0 **30.000→29.842（−0.53%）**，pipe1 **30.000→29.472（−1.76%）**；
  - 配对率分母取 `min(frame_in)`，99.74% 只说明“已到达的帧里 99.74% 配上了”，**不代表吞吐**。
- 三例都没有错配：算法在两侧不齐时丢弃较旧帧，代价是丢帧，不是配错。

**C04S 的拼接交付损失（配对成功 ≠ 发布成功）**

| 窗口 | 配对数 | combine 发布数 | 交付率 |
|---|---|---|---|
| 0–60 s（负载中） | 1700 | 880 | **51.8%** |
| 60 s+（负载后） | 3237 | 3237 | 100% |
| 全程 | 4937 | 4117 | 83.4% |

- 配对成功 4937 对，但 `combine_recycled` 累计 **820**，恰好等于发布差额（4937−4117=820），且全部发生在负载窗口。
- 机制：CPU 满载时订阅侧消费变慢，拼接缓冲队列深度不足，采集侧回收（丢弃）拼接帧；配对链路本身没有失败。
- 与 03-drop 的结论一致：**负载下先丢在“接收/拼接缓冲”，不是丢在 V4L2 取帧**。

## 4. 失败事件（修复后只保留真实失败）

`sync_pair ok=0` 已按 reason 分别限流 1 条/秒，且：

- **两路都空不输出**（100Hz 轮询、30fps 下是正常帧间状态）；
- 单侧缺帧需**持续 ≥100 ms（约 3 帧）**才输出，两路固有 ~3 ms 到达差不会被误报。

| 用例 | ok=0 条数 | 明细 |
|---|---|---|
| C04 | 0 | — |
| C07 | 0 | — |
| C04S | 3 | `missing_frame` ×1（missing=2，单侧缺帧持续）；`diff_over_tol` ×2 |

C04S 的两条超容差原始证据：

```
frame_id_a=49   frame_id_b=47   diff=30367375 ns  tol=16666666 ns
frame_id_a=1167 frame_id_b=1165 diff=30363166 ns  tol=16666666 ns
```

- 两例都是 **pipe0 比 pipe1 超前 2 帧**（约 30.36 ms > 容差 16.67 ms），算法拒绝配对并等待，随后按过期丢弃；
- 这正是“用时间戳配对、不比 frame_id”的边界：没有配错，但会停下来丢帧；
- 负载期共 13 帧未配上（4950−4937），与 2 条超容差事件方向一致。

## 5. 口径辨析：1 ms 该量在哪里

| 测量点 | C04 | C07 | 说明 |
|---|---|---|---|
| 触发时刻 `ts_trig` 差（05） | —（无触发） | **0** | 硬件同触发，同一拍 |
| 取帧 stamp 差（本轮） | 2.96 ms | 1.28 ms | 含曝光起点差 + 曝光时长差 |
| 曝光起点差（推算） | ≈1.68 ms | **0** | C04 = 2.96 − 1.28（1.28 由 C07 标定） |
| 曝光中点差（推算） | ≈1.68 ms + Δexp/2 | **0.643 ms** | C07 的 `Δexp/2` = 1286/2 |

- 若 B-02 定义为“曝光起点/中点同步”，C07 为 0 / 0.643 ms，**满足 ≤1 ms**；
- 若定义为“配对点 stamp 差”，C07 的 1.28 ms **不满足** 1 ms，C04 的 2.96 ms 更不满足。
- 本轮按方案原文取**配对点 stamp 差**，故报告 1.28/2.96 ms；口径选择留给评分层裁决。

## 6. CPU 压力正向对照（C04S）

| 窗口 | 配对数 | 间隔 p50(ms) | p99(ms) | max(ms) | >50ms 次数 |
|---|---|---|---|---|---|
| 0–5 s | 128 | 33.4 | 122.0 | 150.0 | 33 |
| 5–60 s（负载中） | 1572 | 32.2 | 98.2 | 115.4 | **287（18.3%）** |
| 60–120 s（负载后） | 1800 | 33.3 | 44.5 | 48.6 | 0 |
| 120 s+ | 1436 | 33.3 | 36.5 | 48.7 | 0 |

- CPU0 满载期间配对节奏出现 ~115 ms（3.5 帧）的停顿，负载结束后立即恢复。
- **配对差不受压力影响**（2.97 ms，与 C04 相同）——压力影响到达节奏，不改变固定的两路偏移。

## 7. 埋点与分析链

- 新增事件 `sync_pair`（`EVAL_EV_SYNC_PAIR = 1u << 8`）：
  - 成功：配对成功**且拿到拼接缓冲**后一行，`tag/ok=1/n/pipe_a/pipe_b/frame_id_a/frame_id_b/ts_a/ts_b/diff_ns/tol_ns`；
  - 失败：`missing_frame` / `missing_after_drop` / `diff_over_tol` / `no_buff`，带 `missing` bitmask 与 `n`（队列数）。
- 三条防噪规则：两路都空不输出；单侧缺帧需持续 ≥100 ms；按 reason 分别限流 1 条/秒。
- 只改 `src/hobot_mipi_cap.cpp` 的 `sync_task`/`sub_sync_task`，**未改配对逻辑**；顺带把全局 `TOLERANCE` 改为函数内局部量，辅流容差按 `sub_fps` 计算（原实现用主码流 fps）。
- 分析：`sync_metrics` 输出配对率（分母 `min(frame_in)`）、差的分位、`frame_id` 错配、失败原因、`missing_idle/asym` 拆分、配对间隔。
- 单测 **39 项全过**（新增正常配对、错配、缺帧、超容差、idle/asym、单侧全失效、零配对率告警）。

## 9. 局限

- `tag=sub`（辅流拼接）未覆盖：C04/C07 的 `sub_stream_enable=false`；辅流容差已改为按 `sub_fps`，但行为待 C06 满载轮次验证。

- C07 的 1.28 ms 已定位为左右曝光时长差（AE 未同步）；“`info.timestamps` 与 `tv` 的跟随关系”目前靠同 run 数值吻合（差 2.5 µs），需复跑确认。
- 未测 `sync_ae=true`：这是把 C07 的 1.28 ms 压到 1 ms 以内的最直接手段，建议下一轮复测。
- C04S 只压了 CPU0 60s，未做更长时间/其它核的压力曲线。
- 1 ms 口径的测量点（触发 vs 取帧 stamp）尚未由评分层定稿。
