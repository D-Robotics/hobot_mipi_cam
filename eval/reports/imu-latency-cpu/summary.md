## 1. 结论（两例均 PASS）

| 指标 | HI2（仅 IMU） | HI1（IMU+图像） | 判定 |
|---|---|---|---|
| IMU 延迟 p50 | **3.05 / 3.18 / 3.04 ms**（空载/压力/恢复） | 3.83 / 3.83 / 3.84 ms | ✅ |
| IMU 延迟 p99 | **4.06 / 4.28 / 4.03 ms** | 10.52 / 9.39 / 7.43 ms | ✅（HI2 判据 5ms；HI1 参考 50ms） |
| IMU 帧率 | **202.4 fps 恒定** | 202.2 fps 恒定 | ✅ 无丢样 |
| 图像延迟（剥离 boot 偏移后） | — | 左 18.5 / 右 24.7 ms（p50） | 记录 |
| 图像压力敏感性 | — | 左 p95 31.09 → 31.12（**1.00×**）→ 31.49（1.01×）<br>右 31.15 → 30.71（0.99×）→ 32.43（1.03×） | ✅ ≤2× |

**关键结论**：
- **产品 IMU 采样→接收延迟 ≈ 3.0~3.8 ms**，3 核 CPU 压力下无变化（±0.2ms）；
- 同时订阅图像时 IMU p99 从 4.1ms 升到 ~10ms（同机多进程调度抖动），仍远小于图像周期；
- 图像延迟对 3 核 CPU 压力不敏感（1.00~1.03×）。

## 2. 本轮改进解决了什么（改前 vs 改后，同一被测算据）

| 问题 | 改前实测 | 改后实测 |
|---|---|---|
| **IMU 被图像反序列化阻塞** | 单 executor 单线程：HI1 IMU p50 **1526ms**（压力期反而 56ms，反向） | IMU 独立**进程**订阅：HI1 IMU p50 **3.83ms** |
| 仅线程/节点分离（中间试验） | p50 245ms / p95 250ms 双峰（= depth 50 ÷ 200Hz，队列满） | —（已放弃，GIL 仍被图像持有时阻塞） |
| **启动瞬态（IIO 缓冲积压）** | 前 5s 仍有 9.3s 延迟旧样本，p99 153ms | 预热 15s + 按 t0 过滤：**无秒级样本** |
| 阶段边界 | 分析按「首样本+pre_stress」推算 | 脚本写 `<stem>.phases.json`，分析直接采用（精确） |
| 分段统计 | 只有全程混合值 | 表内**空载/压力/恢复分段** + 全程对照 |

## 4. 脚本改动（本轮，4 条建议全部落地）

1. **IMU 与图像彻底隔离**：IMU 用 `multiprocessing`（spawn）独立进程订阅并写 CSV，主进程只负责图像；
   中间试验过"两个 Node + 两个线程 + best_effort depth=50"，实测仍有 250ms 固定积压，故必须进程级隔离。
   IMU QoS 改 **best_effort depth=50**（与产品 best_effort 消费者一致，不再因订阅端变慢积压）。
2. **分段统计**：汇总表输出 空载/压力/恢复 三段 + 全程，并打印每段 fps。
3. **预热丢弃**：新增 `--warmup`（默认 5，用例配 15）；预热结束清空缓冲后才开始计时。
   实测 IIO 缓冲可积压约 9s，**5s 不足、15s 足够**（HI1 改后无 >60ms 样本）。
4. **记录域与偏移**：启动时打印各 topic `recv−stamp` 最小值（最接近纯偏移）；写
   `<stem>.phases.json`（t0/压力边界/warmup/域/偏移提示），供离线分析精确分段。

兼容性：CLI 原参数不变（新增 `--warmup`、`--phases_output`）；CSV 列不变；旧 CSV 无 sidecar 时
分析器自动回退按参数推算。

## 6. 局限

- 压力 3/8 核（保守）；更重负载未测。
- HI1 的 IMU p99（~10ms）含同机多进程调度抖动，非产品延迟；严格 IMU 结论取 HI2。
- image 的 boot 偏移本轮达 **371~373ms**（历次 20/38/117ms/3.9s），剥离后才可比。
- `max` 仍有 ~55~100ms 的偶发样本（p99 之外），未深挖（疑系统调度/GC）。
